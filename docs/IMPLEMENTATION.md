# General framework implementation

[Documentation index](README.md) · [Project README](../README.md) · [Agent instructions](../AGENTS.md) · [Development guide](DEVELOPMENT.md)

The framework contains no customer org, profile name, language/currency restriction, predefined stages, fixed business scenarios or built-in object page adapters. Former business adapters and the local pilot map are archived only under ignored `.reference`; they are excluded from source modules and packaged artifacts. The user test module remains empty.

## Default Page Object Model

Page Object Model is the default learning/replay architecture: session/persona-scoped `PageObjects` encapsulates stored controls, while `CaseRunner` retains deterministic assertions. New learning groups controls by route context and isolates model revisions per attempt; Java consumers use `SfTestContext.page(id)`. New case IDs and CLI output filenames are normalized to `TST_`, with existing recipe IDs/checksums unchanged on load. See [POM and naming](PAGE_OBJECT_MODEL.md).

## Connection and identity

Configuration accepts production, sandbox, scratch and other deployment labels as metadata, without hostname/edition gates. Trusted HTTPS origins are exact and project-defined, including custom domains and approved frames. Conventional My Domain/Lightning pairing is derived when applicable. JWT token origin and audience are independent; bootstrap routes are app-relative and configurable. Authentication routes are excluded from business navigation/observation.

Identity aliases are dynamic `Persona` values rather than a Sales/Service enum. Configurations declare aliases and secret references; `@SfCase.persona` is a string. Contexts remain isolated by alias. Browser locale/timezone are applied only when configured; labels are observed as displayed. Language and currency do not gate execution. Each target's username, permissions and UI settings determine its actual accessible surface.

JWT mode delegates to Salesforce OAuth/UI Bridge with validated destinations. Storage-state mode consumes an existing authorized cookie/localStorage/IndexedDB session, validates origin boundaries, registers stored credentials and leaves the external file untouched. It requires session renewal through the installation's authentication process when expired. No credentials or session files are shipped.

## Mapping and storage

Discovery readiness compares route, semantic targets/attributes, text, values and checked/disabled states across four matching observations. Ephemeral node IDs and capture timestamps are excluded. This gate does not establish a business outcome; continuously changing content may require a narrower named scope. See [the readiness and runtime review](RELIABILITY_REVIEW.md) for the regression evidence.

`UiMapper` observes explicit routes/scopes and uses provider-neutral `ModelClient` only to name observed reusable controls. Model output cannot execute actions. Schema validation, coverage, uniqueness, node references, scope collisions, model/time budgets and fresh post-model observations precede a write. Invalid JSON/protocol gets at most one repair call; transport failures propagate.

Named dialog/region/group/form and row scopes are generic. `edit-dialog` detects edit controls structurally rather than by an English Save label. Record rows are excluded from reusable-control mapping; recognized record links produce one parameterized record-name template per scope. Bound names are never persisted or healed to another record. Custom routes without recognizable record identity need metadata/scopes supplied by the consuming app.

Named-scope cardinality is evaluated across approved frames, allowing a scope to exist only in a child frame while rejecting duplicates across frames. Engine capability `playwright-1.63/semantic-5/query-context-and-frame-scopes` invalidates earlier maps after these identity changes.

Namespaces separate project, org origin/alias, identity/user hash and configured UI settings/profile. Repository documents are versioned, checksummed and bounded to 4 MiB/10,000 entries. Local file locks and optimistic revisions prevent lost updates; writes are atomic. A full explicit scope remap archives its previous repository, replaces only that scope and rejects concurrent edits. Locators survive Maven clean. Engine capability changes require remapping.

Each store now retains one immutable validated snapshot. Every lookup still reads bounded file bytes and computes their SHA-256; identical content reuses the parsed entries, while any different content is parsed and validated again. Size/mtime alone never authorize reuse. External updates, corruption, deletion/recreation and same-size/restored-timestamp edits remain observable. This optimization retains file I/O and does not cache UI nodes or bypass fresh locator resolution.

## Deterministic execution and healing

`AiWorkflowClient` is the default AI transport pipeline in CLI learning/discovery/mapping and JUnit agent/advisor paths. A shared instance reserves physical calls/tokens/optional estimated USD before dispatch, caps serialized input and provider output, and settles valid provider-owned usage. Failed/unknown usage retains reservations. Read-only discovery can reuse exact evidence or make one invalid-protocol repair/explicit stronger-tier attempt. Live actions/judgments and valid failed outcomes do not use that retry/cache path. Learning can reuse an earlier target only after fresh unique strict identity and permitted-role checks. Allure quality summaries aggregate the latest snapshot per instance; unpriced calls remain unknown cost. See [AI workflow](AI_WORKFLOW.md) for policy, accounting and internal browser savings/defect proof.

`CaseSpec` supplies user intent as bounded explicit steps with value/expected-result references. `CaseLearner` optionally plans a UTF-8 text case, then requests only a current node reference for each UI step. Role, semantic uniqueness, fresh context/attributes and schema checks precede storage/dispatch. It uses the existing deterministic executor for the actual action and assertion. Each attempt gets separate locator keys so failed learning cannot overwrite an older recipe's references. Record-link target projections and stored templates omit the runtime record name.

The default workflow compacts read-only wire payloads and sends/reserves task-specific output caps. Bounded case batches group current same-scope intents, validate all IDs/roles and retain transient semantic descriptors. Fresh complete scope context invalidates pending descriptors on UI changes; each remaining descriptor must match one fresh node before normal deterministic execution. Optional batch preflight can defer to single-target discovery without charging a call. An unchanged mapped scope can reuse its persisted entries after exact bidirectional coverage and a second unchanged observation. Output-cap truncation permits one full-allowance primary repair; a response already truncated at that full allowance fails without an identical second paid attempt. See [AI workflow](AI_WORKFLOW.md) for configurable switches and measured limits.

Text plans may extract literal inputs/expectations separately from their steps. Every extracted value must occur verbatim in supplied instructions, pass secret/redaction checks and use a new valid reference name; caller values cannot be overridden. Successful CLI learning writes these values to a separate private parameter file. The recipe never includes runtime values or an AI assertion verdict.

`UiExplorer` maps visible pages through `UiMapper` and lets the model choose only independently enumerated navigation hrefs. The engine excludes record/authentication/destructive/script/download routes and bounds href probes. Model-call/token budgets cover mapping and navigation decisions together. A visited page contributes open/visible-check steps; these are smoke presence checks. Hidden flows require supplied case intent.

`CasePlanner` separates text-to-intent translation from UI execution. `plan-case` constructs a bounded model pipeline but no target authenticator, engine or locator repository; it writes an editable `CaseSpec` and separate private values. Direct text learning delegates to the same planner while sharing its existing learning budget. `validate-case` checks a specification and operation parameters without loading configuration or constructing a model. Neither command emits a verified recipe or claims target correctness. Discovery completion stores its visited checkpoint references, known remaining eligible routes and stop reason in the workflow journal/report without changing recipe schema/checksums. The final capped page is also probed, and the report explicitly excludes complete application/business coverage. See [case workflows](CASE_WORKFLOWS.md).

`CaseRecipe` has a versioned checksummed envelope, namespace hash, engine version, relative routes, locator references and runtime parameter references. `CaseRunner` is in core and has no agent dependency. Preflight rejects mismatched namespaces, missing values/maps and unsupported checked states/keys. Replay polls deterministic expectations using bounded deadlines and executes actions through `HealingLocators`; no model client/advisor is available. CLI commands preserve existing recipe outputs and publish a new recipe only after successful completion evidence.

`HealingLocators` retries the exact stored primary, then unique alternatives, then independently supported fingerprints. Role/container/route/frame identity, stable test/field attributes and confidence/margin checks reject ambiguous or unrelated candidates. Dynamic DOM IDs, positions and field values are not identity anchors. Strict mode retries exact targets only. Read-only mode caches confident repairs in memory; read-write mode persists replacements/history automatically. The deterministic profile blocks framework model calls and AI fallback.

An exact semantic match must also retain the saved frame and have no conflicting stable anchors. Route identity preserves meaningful query state as a digest without storing raw values, normalizes recognized record-ID parameters and omits credential/volatile parameters and fragments. Redaction markers remain parseable. JWT UI Bridge registration masks OTP/CSHC and the complete credential URL, while leaving its public start route out of the credential registry.

Only a pre-dispatch `NODE_STALE` rejection can trigger action-resolution retry. Dispatched interactions are not blindly repeated after uncertain failures. A healed locator never substitutes for a business assertion or changes the expected result. Future consumer tests provide values, outcomes and business workflows. Optional agent record scopes accept an explicit app-relative record route and container; localized choice controls are governed by semantic role rather than English field names.

## Evidence and boundaries

Registered secrets include raw/collapsed-whitespace, escaped JSON/HTML, URL and base64 forms. Values of at least six characters also use case-insensitive/whitespace-flexible matching and bounded trailing-prefix protection; shorter values retain exact matching. This is conservative known-value masking, not certification of arbitrary transforms or values split across DOM nodes. Matching precedes observation clipping, and persisted frame/container metadata is redacted as well.

Browser semantic controls exclude hidden, inert and accessibility-hidden ancestry, including shadow hosts. Screenshot masks still inspect painted pixels in these subtrees. Sensitive rectangles are resolved in viewport CSS coordinates across approved frames and tracked roots before and after capture. A changed/unavailable rectangle or coverage proof withholds the image. The raw PNG remains in memory and is never returned or written; Java pixel masking rounds each rectangle outward, then encodes the returned PNG. This avoids relying on a browser masking overlay surviving document replacement and leaves app DOM unaffected. Consumer PII labels and private evidence ownership still apply.

Browser workers reuse owner-thread processes with fresh contexts. Failed engine initialization releases its partially created context; repeated runtime closure is idempotent and cannot remove a replacement runtime. Explicit operation timeouts use the minimum of caller/attempt budgets and the action cap. Custom multi-select validates the complete visible option set before selection mutation and waits for asynchronous selection state after a single click. These behaviors are maintained by `ReliabilityHarnessIT`.

`FrameworkConfig.Quality` supplies enabled browser-defect gates, bounded issue storage, optional drift/retry limits and exact scoped expiring waivers. `PlaywrightEngine` observes pages/popups, console errors, 5xx responses and failed approved-origin requests after authentication. No response bodies, headers/cookies or URL queries are exported. CLI and JUnit finalization run `BrowserQuality`; business and quality failures retain their evidence and produce failure verdicts rather than silent success. Overflow is always fatal.

`CaseSuite` describes private dataset rows and parameters. Suite preflight validates the selected recipes/maps/values before authentication; execution uses a fresh engine/attempt per row without constructing a model. Independent rows continue unless fail-fast/cancellation stops the selection, in which case later rows remain skipped. `SuiteReportExporter` verifies child data/evidence and renders one Allure report; aggregate success requires every selected row to pass. Raw suite/quality summaries are retained for CI and rebuilding.

Count/state/absence assertions use read-only bounded polling. Counts never heal the target description; zero/hidden requires a previously observed stable anchor and complete route/scope coverage, and changed visible anchored identity cannot establish absence. Learning reuses the earlier target for negative steps. Empty expected-field maps and missing actual fields cannot issue `UiVerification` outcome proof. `sf.expect` supports deterministic read-only custom business predicates in Java cases.

Consumer cases require `RunCoordinator`/CLI execution; direct `SfE2eExtension` launches fail before user class setup. `SelectionPlanner` validates AI exclusions across dependency closure and groups selected cases into contiguous, dependency-ordered classes. Conflicting method orderers and dependencies requiring class interleaving are rejected at planning time.

`DependencyMethodOrderer` supplies the validated order within one Jupiter execution per class, preserving class callbacks and `PER_CLASS` state. `SfE2eExtension.afterEach` finalizes only after user teardown. A coordinator listener reconciles later failed/aborted callbacks before the next method; the complete JUnit summary reconciles class/container failures before the next class. Disabled unstarted cases may omit journals; started attempts still require retained-record manifests. All retained records and evidence survive result reconciliation.

Mapped controls expose actual target-app labels. Accessible names may contain business data, so maps need review before sharing. Secret masking handles object-valued Lightning components as well as standard controls and tracked closed roots. Pre-existing untracked roots, unapproved frames, ambiguous targets or observation limits fail explicitly rather than justifying repair. Limits: 5,000 observed nodes per frame, 20,000 traversed DOM elements, 50 history records per locator.

Reports are stored outside Maven output at `report/<UTC timestamp>`; permanent journals at `.sf-e2e-data`; mappings at `.sf-e2e/locators`. All are ignored by default. `ReportDirectories` atomically reserves timestamp directories shared by JUnit, file workflows and mapping/inspection/validation diagnostics. Full clock precision and UTC ordering are retained; collisions allocate a suffix without modifying an earlier run. JUnit/file-workflow IDs match their directory names. The optional journal tracks standard/custom/managed-package objects without imposing business schemas. Its ownership/uncertain-save guards remain; no records are created by mapping or validation. Shared CI maps require reviewed artifacts and matching namespaces.

File commands acquire reference-counted shared org leases plus exclusive authorized identity leases; the Java coordinator retains an exclusive org lock. Suites add dependency/resource scheduling and bounded owner-thread workers. Fresh contexts and immutable per-row inputs/evidence are preserved with scoped process reuse. Permanent attempt journals precede dispatch. Actual model-call attempts are counted at the transport boundary; replay never constructs a provider.

Both file workflows and JUnit completion export Allure result JSON and verified PNG attachments, then invoke the bundled official Allure 3.20.1 engine through a local Node.js process without a shell. A bounded child process generates single-file HTML; atomic publication preserves the previous report until rendering succeeds. The runtime engine cache is versioned by the bundled archive hash and protected by a file lock. Ordered step events distinguish passed, failed/broken and unexecuted skipped steps. Default step captures supplement mandatory start/completion and safe failure evidence. Generation metadata records the HTML checksum; `report verify` validates evidence ownership/content and both published HTML copies. `report build` accepts either `case-report.json` or `run-report.json`. See [Allure reporting](ALLURE_REPORTING.md).

The [advanced guide](ADVANCED_CAPABILITIES.md) specifies REST authorization/version/usage/pagination/oracles, metadata-aware owned fixtures, explicit file/page/widget recipe values, axe/visual/performance gates, private diagnostics, external release runners and native sessions. Maps remain browser/capability-specific; Chromium uses its CDP root probe while other engines explicitly declare tracked-root coverage. Native PNGs remain confidential rather than browser-masked evidence. Generalization does not establish private customization/device compatibility or autonomous traversal of hidden flows; see verification.
